## 1. Продукт

**Samkraft превращает время и навыки людей, живущих в Швеции без полного доступа к рынку труда, в проверяемый общественный вклад** — и возвращает им подтверждение этого вклада (intyg, рекомендательное письмо, портфолио), а обществу — выполненные локальные проекты и структурированные предложения в администрацию.

Три контура ценности:

1. **Проекты** — организации и жители создают проекты, волонтёры присоединяются, часы фиксируются и подтверждаются.
2. **Документы** — за подтверждённое участие: сертификат + рекомендательное письмо с verify-ссылкой.
3. **Голос** — любой пользователь пишет предложение для коммуны своими словами на своём языке; AI приводит его к стандартному шведскому формату; человек проверяет и отправляет.

## 3. Роли и организации

Сейчас в коде: `migrant | volunteer | mentor | municipality_admin | pending_admin`. Проблемы: роль «migrant» сама по себе — чувствительный маркер статуса и она дублирует «volunteer» функционально.

**Целевая модель:**

- **Индивидуальные роли:** `participant` (объединяет migrant+volunteer; миграция данных тривиальна), `mentor` (подтверждает часы/навыки, подписывает письма), `municipality_admin`, `admin`. Поле `role` остаётся в `users` для обратной совместимости.
- **Организации** (новая сущность `organizations`): `ideell_forening` | `kommun` | `foretag` | `politisk_org` | `informell_grupp`. У организации — участники с орг-ролями (`owner | manager | member`). Проект принадлежит либо пользователю, либо организации.
- **Верификация организаций:** admin проверяет (organisationsnummer для юрлиц) → бейдж «verifierad». Только верифицированные `foretag` могут публиковать оплачиваемые роли; только верифицированные организации — вести civic-кампании.

Кристина создаёт организацию `politisk_org` → создаёт проект-кампанию → сама добавляет/принимает волонтёров через дашборд проекта. Платформа не «принадлежит» партии — партия просто один из организаторов проектов.

## 4. Типы проектов — матрица правил

Новое поле `projects.project_kind`:

| project_kind | Кто создаёт | Разрешённые роли | Итоговые документы | Особые правила |
|---|---|---|---|---|
| `ideell` (по умолч.) | Любой пользователь / ideell_forening | volunteer | Intyg + рекписьмо | Возмещение расходов — только флаг «reskostnad» |
| `kommunal` | kommun / municipality_admin | volunteer, praktik | Intyg + рекписьмо от коммуны | Привязка к бюджету коммуны (поля уже есть) |
| `civic` (кампании) | Верифиц. организация | volunteer | Intyg + рекписьмо | Участие непублично по умолчанию; контент-правила §9; DPIA |
| `kommersiell` | Верифиц. foretag | **только paid, praktik** | Anställningsintyg вне платформы | Волонтёрские роли заблокированы на уровне БД (CHECK) и UI; текст-предупреждение об AT-UND |

Это прямой ответ на идею «волонтёр → работа»: в некоммерческих проектах человек накапливает подтверждённые часы и рекомендательные письма, а коммерческие организации на той же платформе публикуют **оплачиваемые** роли и видят проверенные портфолио кандидатов. Конверсия происходит через документы, а не через бесплатный труд в бизнесе.


## 6. AI-конвейер «Предложение администрации»

**Сценарий:** Пользователь пишет своими словами на любом языке («во дворе на Storgatan нет света, страшно ходить») → выбирает коммуну → Edge Function отправляет в Claude → возвращается структура стандартного формата:

```
Rubrik            — заголовок (1 строка)
Bakgrund          — проблема, факты, место
Förslag           — конкретное предложение
Förväntad nytta   — польза и для кого
Berörd nämnd      — предполагаемый комитет/управление (AI-гипотеза, помечена как гипотеза)
+ перевод резюме на язык автора для проверки
```

**Правила конвейера (важно):**

1. **Human-in-the-loop:** AI-версия — черновик; пользователь обязан прочитать (перевод на его язык прилагается), отредактировать и явно утвердить. Никаких автоматических отправок (GDPR ст. 22 + качество).
2. **Отправка — официальным каналом коммуны:** кнопка «Отправить в {kommun}» открывает форму e-förslag/medborgarförslag коммуны с готовым текстом для копирования (в `municipalities` добавляем `proposal_channel_url`, `proposal_channel_type`). Копия и статус трекаются в Samkraft. Позже, с коммунами-партнёрами, — прямая интеграция.
3. **Промпт-гигиена:** системный промпт фиксирован на сервере; пользовательский текст — только как data; фильтр на попытки сгенерировать оскорбления/агитацию; лимит N предложений/день.
4. **Данные:** для AI-запроса передаётся только текст предложения (без имени/email); Anthropic API с `store=false`-подходом; текст предложения — обычные персданные, но просим не включать чувствительное (подсказка в UI).
5. Модерация: предложения публичны для поддержки другими только после ревью модератора (анти-спам, анти-hate).

Это же ядро переиспользуется для стандартизации описаний проектов (черновик проекта своими словами → структурированная карточка).

## 7. Сертификаты и рекомендательные письма

**Сертификат** (за участие) — уже заложен: hash + verify-URL `/api/certificates/verify/:hash`. Сохраняем.

**Рекомендательное письмо** — новое, строже:

- **Критерии выдачи (enforced в БД/функции):** участие `completed` + часы подтверждены ответственным (creator или mentor) + минимум часов (настройка проекта, по умолчанию 20) + проект не в статусе `draft`.
- **Содержание:** автогенерируемая фактическая часть (проект, роль, период, часы, навыки — из данных) + личный текст автора письма (человека!). AI может предложить черновик личной части автору, но подписывает человек с указанием имени и роли.
- **Форматы:** PDF на шведском + английском, QR/verify-URL, хранение в приватном Storage, доступ по signed URL.
- **Юридически:** это intyg/rekommendationsbrev — обычная практика, специального закона нет; запрещаем формулировки-обещания трудоустройства. Письмо от организации подписывает уполномоченный член организации.

## 9. Пилот «Din röst 2026» (нейтральная кампания явки)

**Рамка:** проект типа `civic`, организатор — организация Кристины (открыто указана как организатор), **содержание — строго нейтральное**: «у тебя есть право голоса — используй его», материалы только из [val.se](https://www.val.se/) и [Informationsverige](https://www.informationsverige.se/sv/om-sverige/att-paverka-i-sverige/13-september-ar-det-val-i-sverige.html) (есть готовые материалы на многих языках). Никакой агитации за партию на платформе — это условие в правилах civic-проектов, принимаемое организатором при создании.

**Почему нейтральная (для разговора с Кристиной):** (а) партийная агитация превратила бы каждый список участников в реестр политических симпатий — особая категория данных GDPR ст. 9, недопустимо для аудитории мигрантов; (б) нейтральность сохраняет право платформы на муниципальные деньги и гранты; (в) явка среди родившихся за рубежом систематически ниже ([Delmi](https://www.delmi.se/media/rncdlnlv/pb-webb-2022_7.pdf)) — повышение явки само по себе результат, который партия может записать себе в актив.

**Задачи волонтёров кампании:** перевод/раздача официальных материалов, информационные встречи «как проголосовать» (языковые кафе, förening), сопровождение к участкам досрочного голосования, посты в диаспоральных сообществах. Каждая задача — в `project_tasks`, часы — в `volunteer_hours`, в конце — intyg и рекомендательные письма. Это полный тестовый прогон всей платформы.

**Таймлайн (жёсткий):**

| Дата | Событие |
|---|---|
| до 20 июля | Фаза 0+1 платформы готова (см. §11), проект создан, DPIA пройдена |
| 20 июля – 25 авг | набор волонтёров, обучение, материалы |
| **26 августа** | старт förtidsröstning — пик активности |
| **13 сентября** | valdag |
| 14–30 сентября | подтверждение часов, выдача intyg/писем, отчёт о пилоте → кейс для коммун |

**Данные:** не собираем и не храним: за кого голосовать, партийные симпатии, гражданство/статус. Участие в civic-проекте скрыто из публичных портфолио по умолчанию (opt-in). Отдельное согласие `civic_participation`.

## 10. Безопасность и соответствие

1. **RLS — приоритет №1.** Фронтенд ходит в Postgres напрямую с anon key; без включённых политик любой может читать/писать чужие данные. В `supabase_schema_v2.sql` — политики для всех таблиц (шаблон: свои строки — RW, публичное — read, менеджеры проекта — по membership). После применения прогнать Supabase Advisors (security).
2. **Секреты:** Anthropic API key, email-ключи — только в Supabase Edge Function secrets. В браузере — только anon key + Turnstile site key.
3. **Storage:** приватные бакеты (letters, attachments), выдача по signed URL с TTL; аватары — публичный бакет.
4. **GDPR-операции:** экспорт своих данных (JSON), удаление аккаунта (soft-delete 30 дней → анонимизация: письма/сертификаты сохраняют hash-проверяемость без имени в открытых данных), реестр обработки, DPIA для civic-проектов и AI-конвейера.
5. **Модерация:** очередь для новых проектов (`pending_review` уже есть в статусах) и предложений; кнопка report; аудит-лог действий админов.
6. Rate limiting на Edge Functions; Turnstile на регистрации (уже есть).

## 12. Главные риски

1. **Правовой:** коммерческие проекты без строгой матрицы §4 = риск соучастия в dold anställning. Митигируется технически (CHECK в БД) + юрконсультацией до фазы 3.
2. **Политический:** ассоциация платформы с одной партией отпугнёт коммуны и пользователей. Митигируется: нейтральные правила civic-проектов, публичная политика нейтральности, приглашение организаций разных цветов.
3. **Временной:** 7 недель до förtidsröstning. Если фаза 1 не успевает — пилот стартует на минимуме (проект + заявки + часы вручную), задачи/лента догоняют.
4. **Технический:** дрейф схемы и отсутствие RLS — сейчас это два реальных пожара; фаза 0 обязательна перед любым набором пользователей.
5. **Продуктовый:** двусторонний рынок (проекты ↔ волонтёры) холодный на старте. Пилот Кристины решает проблему первого проекта; следующие 5–10 проектов надо привести руками (Röda Korset, studieförbund, языковые кафе).
